# Editorial model v0.1

## Purpose
Archive the Islamic technology ecosystem, make existing resources easier to discover, evaluate their current usefulness, and expose areas where community effort may be better directed.

## Audience priority
1. Developers, contributors, builders, and technical decision-makers.
2. End users, especially Arabic-speaking users.

## Inclusion principle
Include digital resources that perform a useful digital function or represent a product, service, platform, developer resource, or technical surface that can be used, integrated, improved, compared, or studied as part of the ecosystem.

Examples that may be included:
- applications
- websites and web services
- APIs
- libraries and SDKs
- repositories
- platforms
- developer tools
- directories/search tools

Not a general Islamic library:
- books and PDFs are not included merely because they are useful references.
- datasets are not a current collection priority, though the schema may later support them.

## Evidence rule
A seed list is discovery evidence, not authoritative metadata.
Prefer:
1. official source
2. official documentation
3. primary repository
4. store listing
5. direct testing
6. independent review
7. community feedback

Editorial assessments should remain clearly separate from verified metadata.

## Gap rule
Gap status is editorial in the current phase. Numeric scoring/thresholds are intentionally deferred. Each gap should still record its confidence, rationale, evidence, and last review date.

## Maintenance
A resource can start as `indexed` and become richer later. Completeness is progressive by design.
